# Internationalization (i18n)

As-built reference for UI language support. Pairs with [`architecture.md`](./architecture.md) and the Cursor rule [`.cursor/rules/nuxt3-standards.mdc`](../.cursor/rules/nuxt3-standards.mdc).

---

## What is localized

| In scope | Out of scope |
| -------- | ------------ |
| Chrome: nav, settings, auth, feed UI, command palette, shortcuts, empty states, SEO titles | User-authored content (task titles, post bodies, epic names) |
| Toasts and client-side error fallbacks | Server `createError` / API `statusMessage` strings (stay English; map on the client when showing a toast) |
| Status / role / priority labels via i18n key maps | Database rows or per-user locale on the server |
| Day.js month/weekday names + `Intl` date formatting | Translating sample seed data titles |

**Locales:** `en` (default), `vi`, `zh-CN`, `zh-TW`.

**Routing:** `@nuxtjs/i18n` `strategy: 'no_prefix'` — URLs stay `/feed`, `/tasks`, etc. Language never appears in the path.

## Runtime flow

```
LanguageSwitcher / Settings
        │
        ▼
useSettings.update('locale', code)     ← persists mgmt:settings:v1
        │
        ▼
plugins/i18n-locale.client.ts
        ├── i18n.setLocale(code)
        ├── dayjs.locale(DAYJS_LOCALE[code])
        └── document.documentElement.lang = INTL_LOCALE[code]
        │
        ▼
$t / useI18n().t  ← messages from i18n/locales/{code}.json
```

### Boot order

1. `@nuxtjs/i18n` may set an initial locale from the `mgmt_locale` cookie / browser language (`detectBrowserLanguage` in `nuxt.config.ts`) when no stronger preference wins.
2. `useSettings` hydrates from `localStorage` key `mgmt:settings:v1` (includes `locale`).
3. `plugins/i18n-locale.client.ts` syncs **settings → i18n** on boot, then keeps both sides aligned:
   - settings change → `setLocale` + dayjs + `html lang`
   - i18n `locale` change → `update('locale', …)` so the cookie/settings stay consistent

Saved `locale` in settings is the source of truth after the first visit.

### Where users change language

| Surface | Component | Variant |
| ------- | --------- | ------- |
| **Settings → Language** | `LanguageSwitcher` | `buttons` |
| **Header account menu** | `LanguageSwitcher` | `select` |

Both call `useSettings().update('locale', code)` only; the plugin applies side effects.

## File map

| Path | Role |
| ---- | ---- |
| `nuxt.config.ts` → `i18n` | Module options: locales, `no_prefix`, cookie detection |
| `i18n/locales/en.json` | Source of truth for keys (nested namespaces) |
| `i18n/locales/vi.json` | Vietnamese |
| `i18n/locales/zh-CN.json` | Simplified Chinese |
| `i18n/locales/zh-TW.json` | Traditional Chinese |
| `types/locale.ts` | `AppLocale`, `isAppLocale`, `DAYJS_LOCALE`, `INTL_LOCALE` |
| `composables/useSettings.ts` | `Settings.locale` + persist/read |
| `plugins/i18n-locale.client.ts` | Sync settings ↔ i18n ↔ dayjs ↔ `html[lang]` |
| `components/LanguageSwitcher.vue` | UI control |
| `types/task.ts` | `STATUS_I18N_KEYS`, `ROLE_I18N_KEYS`, `PRIORITY_I18N_KEYS`, `RECURRENCE_I18N_KEYS` |

Nuxt i18n v10 defaults `restructureDir: 'i18n'` and `langDir: 'locales'`, so message files live under **`i18n/locales/`** (not a top-level `locales/` folder).

## Message namespaces

Keys are nested under namespaces such as:

`nav`, `auth`, `settings`, `profile`, `feed`, `tasks`, `calendar`, `epics`, `analytics`, `admin`, `common`, `toasts`, `status`, `roles`, `commandPalette`, `shortcuts`, `empty`, `seo`, `home`, `export`

When adding copy:

1. Add the key to **`en.json` first**.
2. Mirror the same key path in `vi.json`, `zh-CN.json`, and `zh-TW.json`.
3. Use `$t('namespace.key')` in templates or `const { t } = useI18n()` in script/composables.

### Labels (enums)

Do not hardcode English status/role/priority strings in UI. Prefer:

```ts
import { STATUS_I18N_KEYS } from "~/types/task";
const { t } = useI18n();
t(STATUS_I18N_KEYS[task.status]);
```

Deprecated English maps (`STATUS_LABELS`, `ROLE_LABELS`, …) remain only as non-UI fallbacks.

### Dates

After locale sync, Day.js formats use the active pack (`vi`, `zh-cn`, `zh-tw`). For `Date#toLocaleDateString`, pass `INTL_LOCALE[settings.locale]` (or the matching BCP 47 tag) so formatting follows the UI language, not only the browser default.

### Vue I18n special characters

Literal `@` in messages must be escaped as `{'@'}` (linked-message syntax). Plural pipes use vue-i18n form: `"one | other"` with `t(key, count)`.

## SEO titles

Pages that set a document title should use `useSeoMeta` with `t('seo.*')` (or a computed that re-reads `t` when `locale` changes) so switching language updates the tab title without a reload.

---

## What not to do

- Do not invent a second i18n stack (custom dictionaries, Pinia locale stores, etc.).
- Do not add `/en/...` route prefixes unless the product decision changes away from `no_prefix`.
- Do not store locale on the user row in MySQL — preference is device-local like theme and density.
- Do not leave new UI strings as hardcoded English; add keys to all four locale files.
